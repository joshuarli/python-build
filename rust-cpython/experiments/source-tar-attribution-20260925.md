# Source tarfile regression attribution, 2026-09-25

**Verdict: locate the hybrid regression at `zlib._ZlibDecompressor.decompress`; do not promote this hybrid.** Two diagnostic `cProfile` passes per installed interpreter gave identical work and call counts. The hybrid spent 41.48 and 41.71 ms more in 1,178 decompressor calls for one archive read, while whole `read_archive()` increased by 36.30 and 38.52 ms. The difference propagates through `gzip._GzipReader.read` and tarfile's buffered reads. Hashing, JSON metadata, and tar header parsing did not show a corresponding increase. These instrumented locations agree in scale with the prior unprofiled 10.81% CPU regression over three reads, but profile time is not a speed measurement and cannot divide the C method's cost among wrapper, Rust code, and zlib internals.

The [workload](source_tar_hybrid.py) reads the real locked CPython source archive through `tarfile.open(path, mode="r:gz")`, visits 6,539 members, hashes the contents and metadata of 6,031 regular files, and checks 136,064,031 regular-file bytes. I copied the archive into this lane's ignored scratch, then verified its 44,210,863-byte size and SHA-256 `965dbc9c847b0ed779a16134495b8690c9fc957996d8bcbb83c47089d4e81467` against `rust-cpython/sources.lock.json`. Its output digest was `4274d870abacbefea6bbdb2175de8b4073198e1fd39f34ede1c065b3faf1a805` in every pass, with the expected member, file, and byte counts.

A single scratch harness with SHA-256 `77b9b77bda98177d9b16799c86412363b7e11e03739250689595c269dc775107` performed `archive_digest(path)` before starting `cProfile.Profile.runcall(read_archive, path)`. It checked the complete result after profiling. The call code was identical for both interpreters; runs were serial in control, hybrid, hybrid, control order. `PYTHONHASHSEED=1`, `PYTHONNOUSERSITE=1`, `PYTHONMALLOC=default`, and `PYTHONDONTWRITEBYTECODE=1` were set through `env -i`. No `PYTHONPATH`, `PYTHONPYCACHEPREFIX`, or `DYLD_*` was inherited. The two interpreters retained their distinct PGO builds; their interpreter SHA-256 values were `622ef6135d157b61254ebbce3778fb424a26d91d1fdc365a66d5fd19ba3797d6` and `c3c5e030b2294d9327c4e0f657b85e84514ff131ce2a4cd90d66985fa9295c12`. Installed `zlib` extension hashes were `2aef4049da6abe4b4e6725f2f79f692ef8f8b3148aa87903a0d40cdef3ef50bd` and `34e0cce48e60c1ba6622b98615a0d239a5e48cbe3cb36a428e65c623b7ba970c`.

The installed-cache policy matched across arms, but these were **not source-only imports**. A separate `PYTHONVERBOSE=1` audit showed that both interpreters loaded valid `.pyc` files for `tarfile`, `gzip`, `compression._common._streams`, and `json`; `PYTHONDONTWRITEBYTECODE=1` only stopped new cache writes. Each corresponding source file had the same SHA-256 on both sides. The `.pyc` file hashes differed between installations, so byte identity of the loaded caches is not claimed. Exact relative cache paths, both hashes, validity observations, and audit logs are in the raw data. Imports and the archive SHA precheck happened before profiling.

`cProfile` charges the C call's elapsed duration to the method and includes profiler overhead around Python calls. Parent cumulative times overlap with child times and must not be summed. The earlier [uninstrumented comparison](source-tar-hybrid-20260925.md) remains the speed evidence: seven pairs, each with three reads, had a median hybrid kernel CPU increase of 10.81%. This profile locates the extra work at the decompressor method boundary, but the distinct PGO binaries and lack of native samples prevent a narrower claim about the precise native instructions. No alternative trace was needed because both profiles exposed the C method with stable counts and differences.

The largest per-process RSS was 40,468,480 bytes, and all six logs recorded zero swaps. `/usr/bin/time` wrapped `env`, which execed the one Python process; no child process was spawned, so its CPU/RSS fields cover each timed process. Archive copy/checksum and report processing were outside the timed attempts. Host swap allocation was 243.88 MiB before and after; no competing compiler or benchmark was observed before profiling. No build, dependency, production source, formatter, linter, hook, or push was involved.
