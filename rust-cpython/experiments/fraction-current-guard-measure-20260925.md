# Current guarded `Fraction` ledger diagnostic

**Verdict: retain the optional scanner for its narrow public parsing coverage; performance and memory remain unqualified.** This is one bounded diagnostic on a heavily loaded macOS host. The earlier roughly 7% loaded-host result measured an older `fractions.py`; it is not evidence for the current guard. The candidate used less process CPU in all three cross-side pairs, but control wall drift reached 10.7%, so these timings do not support a publishable wall-speed claim. If a quiet-host result is neutral or slower, the optional route can still be retained for the demonstrated coverage, subject to an explicit cost decision.

Both arms used the same read-only Rust-for-CPython 3.16 executable, SHA-256 `6eeeb64b9eb161d4d5edb9200e79146dabd8acc0f73fcdca48417d0e3c9531bd`. The control overlay copied its pure `fractions.py`, SHA-256 `bf61790248594add2b9e78c4671af35471313552cf8d3e98899a5327e55fd395`. The candidate overlay applied the exact manifest-verified current `0010-rust-fraction-rational.patch` (SHA-256 `a49252164c9f9a16393b46b7d19b980e2ed13e151b0f0e23a6e7acbbf09c2439`) and yielded `fractions.py` SHA-256 `8275fd7933de5062f6d8f82169caa306980ed398fe1376fe1be1906ae458ee6c`. The standalone private extension came from that same patch's `module.c` and `scan.rs`, was compiled with pinned nightly Rust 1.100 and the accepted interpreter's locked LLVM clang and headers, and has SHA-256 `239d5ce5c11eb0d79cbcd93fafb16beda58d451888d233e2faa448661f0dd654` (50,656 bytes). Exact commands, inputs, environment, identities, kernel usage, and failure excerpts are in the compact data files listed below.

Each ledger process used `-B`, `PYTHONDONTWRITEBYTECODE=1`, a fresh empty `PYTHONPYCACHEPREFIX`, and an overlay directory with no bytecode cache. Import audits showed the intended `fractions.py` file on each side and confirmed that the candidate loaded `_rust_fraction_rational` on an eligible input. Every one of the 12 full-ledger attempts (10 timing, 2 memory) produced the checked-in 200,000-record output digest `356356bd5c02a8e41cfb64a19ec168f35a6a752ed9c5e1c7b3b15b2635d284e9` and reported zero process swaps. The deterministic workload includes 160,000 canonical-template rows and 40,000 fallback-template rows; a few underscored-integer templates with small magnitudes also qualify for the native route.

The serial timing order was control/control, control/candidate, candidate/control, control/candidate, control/control. Candidate/control wall ratios in the three cross-side pairs were **0.9164, 0.9920, 0.8910**; kernel user-plus-system CPU ratios were **0.8923, 0.8942, 0.8766**. The two same-side wall ratios were **1.0088 and 0.8932**; CPU ratios were **1.0113 and 0.9755**. Median observed full-process wall time was 4.37 µs per ledger record for control and 3.96 µs for candidate. The host's load averages rose from 14.42/9.73/7.25 to 16.24/10.36/7.52 during the completed run. Host swap use stayed at 243.88 MiB; that is host pressure, not process swap use.

A separate serial control/candidate memory pass reported peak RSS **45,252,608 / 45,875,200 bytes**, a candidate increase of 622,592 bytes, with zero swaps. The timing pairs' candidate-minus-control peak RSS differences ranged from -966,656 to +720,896 bytes. A loaded-host pair cannot settle memory parity. Monotonic timing supplied wall time; Darwin `wait4` supplied kernel user/system CPU, peak RSS, and swaps for each direct child. The ledger process starts no children. For compiler attempts, waited descendants contribute CPU to the recorded child usage; peak RSS is a process peak rather than a simultaneous tree sum.

Run 01 stopped after Rust compilation because clang was missing an explicit SDK sysroot (`assert.h` absent). Run 02 added the sysroot, built the extension, then stopped in the import-audit helper because this interpreter does not expose `fractions.__cached__`. Run 03 used `getattr` for that optional attribute and completed. Every attempt was checkpointed under a unique ID, including failures. No test suite, formatter, linter, hook, full CPython build, or PGO run was performed.
