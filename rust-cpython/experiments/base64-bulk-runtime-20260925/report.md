# Base64 bulk kernel runtime diagnostic

**Decision: inconclusive for public routing.** The optional chunked Rust kernel is about 32% faster than the pinned Rust baseline, but it has no demonstrated margin over staged CPython 3.16 `binascii.b2a_base64`. Keep the optional patch as a kernel experiment; do not integrate a public route from this result.

The run is `20260925T065917-26e0dec7` in the single [evidence file](../data/base64-bulk-runtime-20260925.json). [`probe.py`](probe.py) copied the verified pinned `Modules/_base64/src/lib.rs` into an isolated scratch tree, applied the optional patch to one copy, verified both complete source hashes, extracted the exact encoder definitions, and added the same raw pointer wrapper to each. It compiled both as `cdylib` with `rustc +nightly-2026-09-15 --crate-type cdylib -O -C target-cpu=apple-m1`. This is Rust 1.100.0-nightly, commit `574ff7d98bd6d037e5236a8453029173b32631fd`. The run used the staged pinned 3.16 interpreter and its `binascii` extension. The evidence file preserves the recipe, every compiler command, source/unit/library hashes, toolchain, host, and compiled output identities. The runner atomically checkpoints each attempt into that file under a unique run and attempt ID.

From the repository root, invoke the runner with the staged Python 3.16 binary and `--source` pointing to the verified pinned fork's `Modules/_base64/src/lib.rs`, `--patch rust-cpython/experiments/base64-bulk-chunks-20260925.patch`, `--output rust-cpython/experiments/data/base64-bulk-runtime-20260925.json`, and `--scratch rust-cpython/work/base64-bulk-runtime-20260925`. A rerun creates a new run ID in that evidence file; an existing run ID is refused.

The input is deterministic SHAKE256 data. The two lengths exercise a 1-byte tail and complete 3-byte groups. Each arm encoded about 64 MiB per round, seven rounds per size, with rotated and reversed order. Rust wrote to a reused, correctly sized output buffer through a ctypes FFI call; `binascii.b2a_base64(value, newline=False)` returned a newly allocated bytes object. That favors the Rust kernel for allocation and omits `_base64`'s Python argument parsing, output allocation, and public route checks. The return length and complete encoded bytes matched C before timing; every timed arm's final output digest also matched. Both input and output identities are in the evidence file.

| Input | Baseline Rust | Patched Rust | C `binascii` | Patched/C paired wall ratio |
| --- | ---: | ---: | ---: | ---: |
| 1,048,576 bytes | 569.24 µs | 387.52 µs | 393.37 µs | 0.988 median; 0.973–1.000 |
| 65,538 bytes | 35.97 µs | 24.57 µs | 24.28 µs | 1.020 median; 0.990–1.038 |

These are medians of seven per-call wall observations. Median kernel user CPU per call was 566.67, 384.31, and 387.09 µs at 1 MiB, respectively; system CPU was 3.02, 2.41, and 7.62 µs. At 65,538 bytes user CPU was 35.87, 24.53, and 24.21 µs; system CPU was 0.08, 0.05, and 0.06 µs. Wall time uses `perf_counter_ns`; user and system CPU use `getrusage(RUSAGE_SELF)`. All 42 raw samples are checkpointed in the evidence file. Same-arm wall max/min spread was 2.28%, 2.01%, and 1.82% at 1 MiB, and 5.63%, 4.81%, and 3.62% at 65,538 bytes. The small Rust/C differences are within that observed self-noise.

Compiler records use `/usr/bin/time -l` around each direct `rustc` command and `getrusage(RUSAGE_CHILDREN)` deltas. Baseline: 0.73 s wall, 0.13 s user, 0.23 s system, 98,615,296-byte peak RSS. Patched: 0.22 s wall, 0.13 s user, 0.09 s system, 103,841,792-byte peak RSS. The time command covers the direct compiler invocation and its waited descendants; short-lived descendant memory is not independently sampled. The benchmark process peaked at 39,026,688 bytes RSS. Time output reported zero process swaps for both compiles; host swap stayed at 243.88 MiB. Host load average was about 3.97/3.69/3.70 on a 10-CPU machine. This remains a bounded loaded-host diagnostic, not a quiet-host performance qualification.

The FFI comparison checks standard padded, unwrapped encoding for two contiguous byte inputs only. It does not establish behavior for alternate alphabets, omitted padding, wrapping, buffer variants, `binascii` replacement, or a public `base64` route. No full CPython build, PGO, test suite, formatter, linter, or hook ran.
