# Numeric slash `datetime.strptime` experiment

The pinned CPython 3.16 public `datetime.datetime.strptime` path spends substantial time in `Lib/_strptime.py` for a fixed `%Y/%m/%d %H:%M:%S` log timestamp. This format is outside `datetime.fromisoformat`'s input grammar. A deterministic 30,000-row, two-round workload parses 60,000 timestamps, aggregates daily counts and values, and hashes the aggregate. Its public digest was `bb2b012282c2f8f0bad78f553fe946f3f093c96bfb8eca6a5077b5ee2e1a9473` on every measured control and candidate run.

The optional `0007-rust-strptime-numeric.patch` changes `Lib/_strptime.py` and adds a private no_std Rust scanner through `Modules/_rust_strptime_numeric/`. It scans only exact ASCII strings of 19 characters, the exact format string, and the default `datetime.datetime` class while the original `_strptime` binding remains installed. It returns six fields or a fallback sentinel. Python constructs the datetime; invalid dates, subclasses, Unicode digits, alternative widths, and other formats take the original parser path. `rust-cpython/build.py build --variant strptime-numeric --strptime-numeric` selects it independently of the other optional patches.

The one successful diagnostic profile covered 20,000 public parses: 0.24 s wall, 0.22 s kernel user CPU, 26.95 MB peak RSS, zero swaps. cProfile assigned 0.157 of 0.208 s to `datetime.strptime`, including 0.137 s in `_strptime`. The first profile attempt failed to save its profile because the ignored output directory was absent; its workload completed. The native build succeeded in 284.96 s wall, 704.19 s kernel user and 110.91 s system CPU, with 1.83 GB maximum per-process RSS and zero process swaps. Fresh locked-source extraction checked default, numeric-only, and all-optional patch selections. An initial all-optional context collision required narrowing the patch anchors; the final selection changed exactly seven intended paths and the installed `_strptime.py` hash matched source.

Three control/control pairs preceded five alternating complete-process control/candidate pairs. The first control wall time was a 0.373 s cold-cache outlier; the next five control times ranged from 0.336 to 0.344 s. Candidate/control wall ratios were 0.634, 0.641, 0.655, 0.639, and 0.661 (median 0.641). The median kernel user-plus-system CPU ratio was 0.613. Median paired peak RSS changed by +32,768 bytes; every workload process reported zero swaps. Five cold `datetime, _strptime` import pairs had a median wall ratio of 1.007 and kernel CPU ratio of 1.0. OrbStack Helper used about one CPU core during timing, but no compiler or competing benchmark ran and host swap stayed at 243.88 MiB.

**Verdict:** keep this as a promising narrow experiment. Eligible calls bypass `_strptime`'s locale check, regex cache maintenance, and their replaceable global side effects. The scanner's value path has no general semantic parity claim. No separate test suite or semantic runtime probe was run.
