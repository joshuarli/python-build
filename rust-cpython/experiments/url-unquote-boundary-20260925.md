# URL unquote boundary scout, 2026-09-25

## Decision

This covers the escaped credentials in the catalog normalizer and escaped query fields decoded by `parse_qsl`. ## Existing semantics and callers

`Lib/urllib/parse.py` defines `_unquote_impl`, `_generate_unquoted_parts`, `unquote`, and `unquote_to_bytes` around installed lines 791–856. `_unquote_impl` UTF-8 encodes `str`, splits bytes on `%`, and lazily builds a hex-pair lookup table. Valid `%HH` becomes one byte; incomplete or invalid escapes retain the percent and following bytes. `unquote_to_bytes` converts its result to exact `bytes`. Public `unquote` treats `bytes` separately and decodes them with the caller's codec/errors; for a `str` without `%`, it returns the original object after a string-like check. For percent-containing text it splits ASCII runs from non-ASCII text, decodes each run with the selected codec/errors, then rejoins. Thus literal non-ASCII characters survive even when the caller selects an incompatible codec. `None` codec/error values normalize to defaults on this `str` path. A bytes input does not take that normalization branch.

The checked-in `benchmarks/workloads/fixtures/tooling/python_corpus/catalog_service/normalize.py` calls `unquote` on parsed username and password, then quotes them. In `catalog_url_normalize`, the 48-record batch contains two repeated credential cases: eight direct public `unquote` calls per batch, four of them with `%` escapes and four no-percent calls. `benchmarks/workloads/catalog_url_breadth.py` adds `catalog_search_form`: 48 `parse_qsl` calls yield 240 pairs, or **480 fields per batch**. For string queries, pinned `parse_qsl` calls `unquote_plus` for every field, which replaces `+` then calls public `unquote`; many names and plain values exit before decoding, but percent-escaped URL and part values reach it. `catalog_request_path` makes 96 `unquote_to_bytes` calls per batch; those are outside this proposed boundary. The catalog functions and breadth workload check whole-output digests, so they provide public-task correctness gates. The earlier repeated one-URL `cProfile` diagnostic recorded 0.019 seconds cumulative in `unquote`, but its instrumented, synthetic time cannot establish this mixed-batch headroom.

`Lib/test/test_urlparse.py` has only two direct `test_unquote_to_bytes` examples at installed lines 1579–1583. Its `test_parse_qs_encoding` and `test_parse_qsl_encoding` cases at lines 1447–1468 exercise Unicode literals, valid escapes, codec selection, and `errors="ignore"` through query parsing. Those tests do not fully specify public `unquote` subclass, malformed-escape, or byte-input behavior; differential cases against the pinned interpreter are necessary if implementation proceeds. Existing guarded quote changes are in `rust-cpython/patches/0001-rust-url-quote.patch`: `Lib/urllib/parse.py` imports `_rust_url_quote`, and `quote_from_bytes` calls its C/Rust helper only for exact bytes after public validation and fast exits, below the 200,000-byte quote chunk threshold. Its C wrapper owns CPython objects and calls a dependency-free `no_std` Rust scan. Decoder work can extend that private module without a crate or public API change; quotation's guard and 200,000-byte policy do not transfer to decoding.

## Precise candidate boundary

Keep the public `unquote` signature and its order of existing byte dispatch, `%` membership check, and `None` normalization. After these checks, call a private `_rust_url_quote.unquote_ascii` only when `type(string) is str`, `type(encoding) is str`, `type(errors) is str`, and the normalized codec/error values are exactly `utf-8` and `replace`. Compare values only after the exact-type checks, so custom comparison methods cannot enter the new path. The helper checks exact Unicode and `PyUnicode_IS_ASCII` in C without a Python-level O(n) `isascii()` pre-scan; it can return a private miss sentinel for non-ASCII input, letting the unchanged Python generator handle it. This preserves str-subclass return identity and overrides on the fallback path. No-percent input should return before the native call, including `str` subclasses.

The C wrapper reads the exact ASCII Unicode buffer, allocates a bounded byte buffer, calls one Rust percent-decoding scan, then uses CPython's UTF-8 decoder with `replace` to create the final `str`. The Rust scan recognizes exactly two ASCII hex digits after `%`, case-insensitively, and otherwise emits the literal `%` and following bytes; it never parses URL structure or interprets `+`. Output byte length cannot exceed input ASCII length. Let CPython own Unicode decoding, exceptions, and object lifetime so `%FF`, truncated multibyte sequences, embedded NUL, and replacement grouping follow the existing codec. Use the same private C module and Rust archive: source targets would be `Lib/urllib/parse.py`, `Modules/_rust_url_quote/module.c`, and `Modules/_rust_url_quote/quote.rs` in the pinned extracted tree, carried by `rust-cpython/patches/0001-rust-url-quote.patch` or a separately ordered patch. If the Rust function lives in a new file, the `Makefile.pre.in` archive rule must also list it; the one-file option avoids that extra build boundary.

Before accepting a patch, compare public results and exception types/messages with the no-Rust interpreter for all 256 escaped byte values, valid and malformed `%` sequences, adjacent escapes, literal non-ASCII plus escaped bytes, `str` and `bytes` subclasses, `bytearray`/other invalid inputs, `None` and custom encodings/errors, and short through large ASCII inputs. Include no-percent identity checks, `unquote_plus` `+` behavior, `parse_qsl` string and bytes queries, and both catalog digests. The unchanged `test_urlparse` and `test_urllib` suites remain required qualification if the code is later written.

## Headroom measurement and stop condition

The earlier 0.019-second `unquote` diagnostic was collected **before** the guarded quote patch. Removing quotation cost changes `unquote`'s share of the remaining task, so do not use that percentage to approve decoder work. First, on the installed guarded quote candidate, count calls to public `unquote` and classify exact ASCII/default/percent eligibility outside timing for each complete `catalog_url_normalize` and `catalog_search_form` batch. Record lengths, escape counts, invalid escapes, and the fraction of `parse_qsl` calls that exit on no-percent input. Measure a diagnostic profile of those unchanged tasks to bound cumulative and self time in `unquote`, `_generate_unquoted_parts`, and `_unquote_impl`; keep this separate from published wall comparisons. Include `catalog_request_path` as a negative control because its byte unquotes cannot enter this boundary. Measure fresh-process import as well as warm batches because `_rust_url_quote` is imported by the accepted quote patch already, but any extra decoder code may still change installed size or memory.

Proceed to an implementation only if eligible decoding is a material share of the **complete** catalog task and the modeled upper bound exceeds that task's serial self-comparison noise. After implementation, use matched control/candidate installed stages and valid parser bytecode caches, then serial counterbalanced complete-task timing and separate kernel CPU, peak/retained memory, allocation, and installed-size observations. Stop and reject if the guard misses common escaped fields, native crossing erases the full-task gain, the gain is within same-side noise, or semantic differential checks fail. Long strings deserve a separate memory sentinel; there is no reason to borrow quotation's 200,000-byte cutoff without decoding evidence. This scout ran no build, benchmark, test suite, formatter, linter, or source edit.
