# Optional source TAR checksum scan, 2026-09-25

**Keep as an opt-in macOS experiment.** `build --tar-checksum` selects a manifest-pinned source patch on top of the quote-only candidate. The ordinary build still selects the original three patches. The optional URL unquote and TAR patches also apply together to a fresh pinned source tree. The TAR patch changes `Lib/tarfile.py`, `Modules/_rust_url_quote/module.c`, and `Modules/_rust_url_quote/quote.rs`; the installed `tarfile.py` hash matches the patched source. The installed extension exports the CPython initializer and `tar_checksum_scan`.

The guarded call accepts only built-in `bytes` of length exactly 512. CPython owns that object and the two integer results; Rust scans bytes 0–147 and 156–511 as both unsigned and signed octets, beginning each sum at 256 for the eight checksum spaces. Every other input reaches the existing `struct.unpack_from` and `sum` statements. The guard uses literal 512 rather than the mutable `BLOCKSIZE` global. The earlier build using `len(buf) == BLOCKSIZE` and its measurements remain as provisional attempts in the [compact data](data/tar-checksum-integrated-20260925.json); the literal-guard rebuild is the verdict build.

The corrected native Apple Silicon build used the pinned source archive (`965dbc9c847b0ed779a16134495b8690c9fc957996d8bcbb83c47089d4e81467`), locked LLVM 23.1.2, nightly Rust 2026-09-15, ThinLTO, and CPython PGO (`-m test --pgo -j 9`). It completed in **300.31 s wall**, **706.92 s user + 111.13 s system CPU**, **1,815,691,264 B maximum resident**, and **zero reported swaps**. The earlier provisional build used 259.39 s wall, 702.60 s user + 106.13 s system CPU, 1,776,074,752 B maximum resident, and zero swaps. These are separate complete builds; their different wall times are not an incremental cost estimate.

The build command was `python3 rust-cpython/build.py build --variant tar-checksum --tar-checksum`. Each timed workload process ran the selected stage's `bin/python3.16 rust-cpython/experiments/source_tar_hybrid.py .cache/objects/965dbc9c847b0ed779a16134495b8690c9fc957996d8bcbb83c47089d4e81467.blob --loops 3` under `/usr/bin/time -l`. The baseline stage was `/Users/josh/d/python-build-exp-merged-macos-url-20260925/rust-cpython/stage-quote-only`; the candidate was this worktree's `rust-cpython/stage-tar-checksum`.

Five final alternating control/candidate pairs each read all 6,539 members of the locked source archive and streamed all 6,031 regular files (136,064,031 bytes) three times per process through `source_tar_hybrid.py --loops 3`. Every attempt produced output SHA-256 `4274d870abacbefea6bbdb2175de8b4073198e1fd39f34ede1c065b3faf1a805`. The control was the existing read-only quote-only macOS stage. Both sides compiled `tarfile.py` from source: `PYTHONPYCACHEPREFIX` pointed to an empty worktree directory and `PYTHONDONTWRITEBYTECODE=1`; separate verbose imports confirmed source loads. The candidate eagerly loaded `_rust_url_quote` during `import tarfile`; the control did not.

Five provisional comparison pairs before the guard correction also favored the candidate, but are excluded from the final estimate. Every final workload attempt reported zero swaps; host swap allocation was 243.88 MiB before and after this lane.

A separate five-pair cold `import tarfile` diagnostic with the same source-only cache policy had 0.10437 s control and 0.10455 s candidate median external wall. Its RSS pair differences ranged from −1,245,184 to +212,992 B, so it does not establish an import memory or time cost. An earlier five-pair `-I -S` diagnostic is retained in the data: `-I` ignored the intended `PYTHON*` cache environment, so those installed-cache observations are not used for the source-only comparison.

The exact-bytes route bypasses replaceable `tarfile.struct.unpack_from` and `builtins.sum`; callers that monkeypatch either helper can observe a difference on exact headers. The eager private extension import is observable too. This experiment also places TAR functionality in `_rust_url_quote`, coupling unrelated domains under a misleading module name. A TAR-owned private module and explicit handling of these exact-input observations are needed before broader acceptance. The complete archive workload verifies normal source-tar behavior, while no CPython test suite or broader differential suite was run under this lane's instructions. Linux was not built.

`/usr/bin/time -l` measured each full build process tree and each direct workload interpreter, recording kernel user/system CPU, wall, maximum resident, footprint, and swaps. `perf_counter` independently measured workload process wall. No sampler or profiler ran during speed measurements. Maximum resident is a lifetime high-water mark, not aggregate simultaneous build memory; process count and unique/proportional memory were not collected. The [data](data/tar-checksum-integrated-20260925.json) keeps every numerical build, workload, and cold-import attempt, including the provisional runs, paired order, output identities, and the two corrected-recipe decisions.
