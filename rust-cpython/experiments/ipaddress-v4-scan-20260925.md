# Canonical IPv4 scan in a mixed routing task, 2026-09-25

**Recommendation: keep the guarded implementation as a bounded speed proof.** The optional native path now checks on every eligible call that `_BaseV4` still owns its original `_parse_octet` classmethod descriptor and `IPv4Address` has no overriding descriptor. Ordinary post-import replacement at either class therefore returns to the Python parser. The descriptor snapshot is assigned after `_BaseV4` is defined and before `IPv4Address` is defined; the guarded native build completed and installed successfully. Focused value, error, and subclass checks remain unrun under the no-tests instruction, so the matching complete-task output establishes this workload's behavior only.

The [workload](ipaddress_v4_workload.py) generates 30,000 deterministic routing/firewall rows per pass, 80% IPv4 and 20% IPv6, and runs two passes. Each row parses two public addresses and one non-strict network, checks containment and a supernet relationship, and digests normalized public strings and membership outcomes. Input generation, imports, work, and output serialization are included in external wall and CPU. Before implementation, a cProfile pass on 10,000 rows ×2 attributed 0.210 of 0.933 instrumented seconds (22.5%) to 60,022 calls of `_BaseV4._ip_int_from_string`; its 192,088 octet parses accumulated 0.132 s. That is instrumented location evidence, not an uninstrumented CPU share.

The guarded follow-up ran three prior/prior calibration pairs, five alternating prior/guard pairs, five alternating TAR-guard/guard pairs, and five prior/guard cold-import pairs, all serial. Relative to the prior unguarded candidate, the new guard raised median full-process wall **1.53%** (paired range +0.28% to +3.10%) and kernel user plus system CPU **0.01 s** per routing process (range 0.00–0.02 s). Calibration wall drift ranged −3.95% to +1.07%, with the first pair the outlier; CPU drift ranged −0.02 to +0.01 s. Relative to the read-only TAR-guard control, guarded wall fell **9.77%** (paired range 8.50–12.11% faster) and CPU fell **0.08 s** median (range 0.07–0.09 s). Every routing process returned digest `71b21698342ecd72171e968712cf7218d0272ea3cbc856e94797a428a0218180`, 53,392 contained peers, and 60,000 subnet relationships. Five cold imports had median guarded-minus-prior wall +0.00048 s with mixed signs (−0.00218 to +0.00516 s), which does not establish an import effect.

The [measurement recipe](ipaddress_v4_measure.py) sets a fresh empty `PYTHONPYCACHEPREFIX`, disables bytecode writes, clears inherited `PYTHONPATH` and `DYLD_*`, and runs each direct Python child under `/usr/bin/time -l -p` without a sampler. All arms import source. The kernel's lifetime peak RSS, physical footprint, user/system CPU, elapsed time, swaps, output, and every attempt are in the [compact data](data/ipaddress-v4-scan-20260925.json). Guard-minus-prior median peak RSS was −360,448 B (range −589,824 to +393,216 B), and footprint was −327,680 B (range −557,056 to +425,984 B). Guard-minus-TAR-guard median RSS was +196,608 B (range −147,456 to +688,128 B), and footprint was +163,816 B (range −180,248 to +655,336 B). These mixed small directions do not establish a memory effect. All follow-up processes reported zero swaps, and host swap allocation stayed at 243.88 MiB.

The opt-in [source patch](../patches/0006-rust-ipv4-scan.patch) adds a TAR-independent `_rust_ipv4_scan` extension. Its no-dependency `no_std` Rust function scans ASCII bytes without allocation and returns a 32-bit value or a fallback sentinel. The Python dispatch requires `cls is IPv4Address`, exact `str`, 7–15 characters, the original `_BaseV4._parse_octet` descriptor, and no `IPv4Address` override. The C wrapper returns non-ASCII text to Python. Empty, malformed, ambiguous, and out-of-range octets retain the pinned Python parser and its error text; subclasses also keep that path. Fresh verified extractions checked default, TAR, URL unquote, and all optional selections; adding IPv4 changed exactly its seven intended source paths in each matched comparison. The guarded `build --variant ipv4-guard --ipv4-scan` installed `ipaddress.py` with the same SHA-256 as patched source, `32c8c8b0164d57430806c19b3cd5b30342e93c6aec693c6d040011988e378371`, and installed the private extension. It used 280.93 s wall, 702.72 s user plus 109.19 s system CPU, 1,812,692,992 B peak RSS, 39,141,880 B peak footprint, and zero swaps. Locked LLVM 23.1.2, nightly Rust 2026-09-15, ThinLTO, and CPython's native PGO task were used.

The first patch failed to compose with TAR at shared insertion sites. Its failure excerpt, first build, and 16 preliminary measurements remain labeled superseded in the compact data. The previous unguarded candidate and its five final comparison pairs also remain there, with a median 11.59% wall gain over TAR-guard before the descriptor guard was added. The locked source archive was copied into this worktree with an APFS clone and its SHA-256 verified before extraction; no writable build output was shared. No dependency, formatter, linter, hook, remote, or production build recipe changed.
