# Canonical UUID text scanner experiment

**Verdict: retain opt-in for partial Rust UUID coverage; reject performance promotion.** The private Rust scanner reaches the public `uuid.UUID` constructor, while the complete ID indexing task shows no improvement beyond local control variation. Five serial pairs of 100,000 records gave a median candidate/control wall ratio of **1.003** and kernel user-plus-system CPU ratio of **1.000** (the kernel reports hundredths of a second). Three control/control pairs gave median wall ratio **1.016**. Candidate peak RSS changed by a median **+376,832 bytes**, within the roughly 0.8–1.1 MB self-pair direction on this host; all processes reported zero swaps. Five cold `import uuid` pairs had median wall ratio **0.982** and RSS change **+98,304 bytes**. No matched upstream or Linux claim follows from this fork-only macOS comparison. The raw 26 process observations and all diagnostic/build attempts are in [compact evidence](data/uuid-canonical-20260925.json).

The deterministic workload builds 50,000 canonical lowercase UUID strings, parses each twice with `uuid.UUID`, converts each object back to canonical text, groups by rendered prefix, aggregates 128-bit values, sorts the index, and hashes the JSON result. Every control and candidate timing process returned digest `9580055459ba0eeeba05ace7957521e461227f4bf2fe97ed14a2eb7439b4fbc8`. The source SHA-256 is `d15f9cba9c771f2370a4e3c52afed9b3b00fb518ca9d8f9d0094bb9cd333ef28`. Run `uuid_canonical_measure.py` with the strptime-only stage, the candidate stage, and an absent evidence path to reproduce the serial order. It uses `PYTHONHASHSEED=1`, an empty `PYTHONPYCACHEPREFIX`, `PYTHONDONTWRITEBYTECODE=1`, and `-B` for both sides, so both compile installed source. `/usr/bin/time -l -p` supplies per-process kernel CPU, peak RSS, footprint, and swaps; a parent clock supplies wall time. The host had 243.88 MiB swap in use before and after. Unique/private and proportional memory and allocator counts were unavailable.

The control is the pinned Rust-for-CPython commit `b812b4a7b9efaca46b98544a8633b7d7e454166b` with default patches and `--strptime-numeric`; its build report selects no other optional patch. Candidate `--variant uuid-canonical --strptime-numeric --uuid-canonical` uses the same locked LLVM 23.1.2, ThinLTO, `-O3`, Apple M1 CPU baseline, native PGO task `-m test --pgo -j 9`, and pinned Rust nightly. Fresh source patch selections changed exactly 8 intended paths for default, 11 for UUID-only, 14 for strptime plus UUID, and 20 for all optional modes, with reverse checks. Installed `uuid.py` and `_strptime.py` hashes match final patched source. The installed private extension is 51,272 bytes; the aggregate installed native-file size is 31,652 bytes larger than control under the same `.so`/`.dylib`/`python3.16*` count rule. PGO variation can affect the rest of that total.

The first full build compiled and completed PGO, then failed at install because the UUID extension retained an unresolved `_rust_eh_personality` reference from a Rust bounds-check path. Its cost was **266.41 s wall, 699.33 s user CPU, 105.92 s system CPU**, and 1,784,233,984 bytes maximum process RSS. Checked slice access removed that retained path. An incremental make/install succeeded in **37.85 s wall, 22.70 s user CPU, 13.74 s system CPU**, and 98,910,208 bytes maximum process RSS. Both reported zero process swaps. The final extension has no unresolved personality symbol; source and installed identities were checked against the final patch.

The diagnostic public workload profile found `UUID.__init__` at 0.098/0.280 s in control and 0.060/0.230 s in candidate for 60,000 records; the native `scan` took 0.009 s across 60,006 calls. Instrumentation explains the route and is not speed evidence. The `from _rust_uuid_canonical import scan` lookup sits inside candidate constructor self time; caching that function could save some work, but the complete-task wall tie does not justify another native build in this lane.

`0008-rust-uuid-canonical.patch` adds a private no_std scanner for exact lowercase ASCII `8-4-4-4-12` text. It returns a 128-bit integer or a fallback sentinel. Python retains the public object allocation, range check, attributes, and all other inputs. The fast route requires the exact `UUID` class and exact `str`, no version rewrite, and the original `int_` binding. Subclasses, alternate argument forms, malformed or noncanonical text, and changed `int_` take the Python path. The fast route bypasses `str.replace`, `str.strip`, and `int_(..., 16)` on canonical input, including any observation of their call frequency; the `int_` guard does not preserve every possible global instrumentation side effect. No semantic test suite or separate semantic probe was run, by request. This is partial parser coverage only: it does not complete the broader UUID checklist item or establish semantic parity. Retention carries the measured speed and memory debt; broader semantic and Linux qualification remain open.
