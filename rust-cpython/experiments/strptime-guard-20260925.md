# Warm-cache guard for numeric `datetime.strptime`

This record measures the earlier warm-cache guard. A later [binding and import guard](strptime-contract-20260925.md) changes `Lib/_strptime.py`; the wall, CPU, and memory observations below are pre-revision diagnostics and do not qualify the later source.

The optional fixed-width scanner can preserve the ordinary parser's warm path when the cache already holds CPython's canonical `%Y/%m/%d %H:%M:%S` regex. In pinned 3.16 source, `_strptime` first checks the current locale and time zone under `_cache_lock`, possibly rebuilds `TimeRE` and clears its regex cache, evicts an oversized cache, and then uses the cached regex. Its matched ASCII fields normally convert with `int`; `LC_alt_digits` can change conversion if replaced. It also calls `datetime_date` to compute discarded Julian and weekday fields. Those calls and mutable cache entries are observable even for numeric input.

The revised `0007-rust-strptime-numeric.patch` uses the scanner only with the original parser, lock, cache objects, locale getter, date constructor, and `int`; exact input, format, and datetime class; a matching current locale and time zone; the original empty alternative-digit state; a cache within its size limit; and a cached built-in regex with the pinned canonical pattern and flags. It checks locale before reading the cache entry. Cold cache, locale refresh, cache eviction, changed globals, subclasses, and scanner-rejected input use `_strptime`. A rebuilt `TimeRE` conservatively disables the scanner until module reload. The pinned stage confirmed `LC_alt_digits == ()` and regex flags `34` for the canonical pattern.

Fresh verified source extraction and patch application passed for default, numeric-only, and all-optional selections, changing exactly 8, 11, and 26 patch-declared paths. Numeric-only and all-optional produced the same final `Lib/_strptime.py` SHA-256, `882be8f550441861456947c12cf6f5edfa759740dc34f3e5f90a75e4c2da3de7`. The final native opt-in build installed those exact bytes and the private scanner extension. It took 282.32 s wall, 703.78 s user plus 109.86 s system CPU, reached 1,765,769,216 bytes peak RSS, and reported zero process swaps. The reported 39,010,808-byte footprint covers the command process rather than aggregate children. Host swap stayed at 243.88 MiB.

The installed interpreter and the same binary with baseline `_strptime.py` source override each processed three paired complete 60,000-record log-ingest runs. Every output digest matched. Control wall was 0.33 s in each run; guard wall was 0.24, 0.25, 0.25 s. Control user-plus-system CPU was 0.32, 0.31, 0.31 s; guard was 0.23, 0.24, 0.24 s. Median paired guard/control wall and CPU ratios were 0.758 and 0.774. Peak RSS differences were +65,536, +770,048, and +507,904 bytes. `-S -B`, `PYTHONDONTWRITEBYTECODE=1`, and an empty worktree-local `PYTHONPYCACHEPREFIX` forced both arms to source; import probes confirmed the exact source paths and no cached bytecode. These timings are diagnostic because an unrelated container consumed roughly one to two CPU cores; they do not establish a quiet-host gain.

The focused installed-source probe observed 14 candidate and baseline cases with matching values or exception type and message. It covered cold and warm cache, invalid seconds, non-ASCII digits, alternate format, subclass, replaced parser and locale getter, a locale hook that replaces the cached regex, replaced date constructor and alternative digits, replaced regex, and cache eviction. Scanner entry occurred only where eligible; a scanner call that rejected input still fell through to the parser. This is bounded routing evidence, not broad semantic parity. Linux and allocation qualification remain open.

One successful build and its 13-case probe were superseded: that draft read the regex cache before the locale check, so a locale hook could replace the entry after the read. The final patch corrected the order and was rebuilt. Initial source checking also found that the primary checkout's cache lacked the pinned fork blob; a verified companion-lane cache was copied into this worktree before fresh extraction. An early hand-edited patch hunk had an incorrect line count and was fixed before source qualification. The compact [evidence](data/strptime-guard-20260925.json) retains all 32 workload process observations, both build resource records, source and installed identities, probe outcomes, and these failed or superseded attempts.

**Recommendation:** keep the guarded opt-in experiment. It retains a clear loaded-host complete-task advantage over the parser while restoring the ordinary cache and locale boundary. Broader semantic, quiet-host memory and timing, and Linux qualification are required before treating it as a general route.
