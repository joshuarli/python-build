# `shlex.split` binding guard revision

**Verdict: keep this source-only guard revision for the opt-in candidate, pending a quiet-host rebuild and paired performance comparison.** It closes measured observable bypasses in the previous `--shlex-split` route. The prior wall, CPU, peak-memory, and installed-size ratios describe the **pre-guard** candidate; none is a measured result for this revision.

The previous fast path skipped `shlex.StringIO`, the module's `list`, `isinstance`, and `StopIteration` bindings, `collections.deque`, several mutable `shlex` hooks, and private-module import interception. Isolated diagnostics on the prior installed stage showed missing spy calls, an altered exception, and a preloaded fake `_rust_shlex_split` changing output. A descriptor whose equality method always returned true also defeated the previous tuple equality check for parser methods. [Compact evidence](data/shlex-binding-guard-20260925.json) records those observations and the revised overlay results.

`0009-rust-shlex-split.patch` now permits native scanning only while those baseline bindings and parser hooks retain their original identities. It checks `__new__`, `__getattribute__`, `__setattr__`, and `punctuation_chars`, and rejects added `__len__`, `__length_hint__`, or `__del__` hooks that `list(shlex_instance)` can observe. Individual identity comparisons prevent an overloaded equality method from approving a changed hook. The first native import is rejected if a private module was already present or the import hook changed. A trusted first import caches the bound C scanner; later calls require the same module in `sys.modules` and use that cached function, so replacing `module.scan` does not redirect execution or require an extra module attribute lookup. The existing 4,096-character ASCII limit, exact `str` and default-option requirements, and Python fallback remain.

The patch manifest SHA-256 is `de3ae62647a02df5722c6da57db3fe34cab9bc39676a3cc8087d494b2b4ffbaf`. Fresh verified CPython source at `b812b4a7b9efaca46b98544a8633b7d7e454166b` accepted default, shlex-only, candidate-stack, and all-optional selections with intended changed-path counts of 8, 11, 17, and 23, plus reverse checks. The candidate's selected `Lib/shlex.py` SHA-256 is `10afd968308c933f2c7ec0928deebfa1e1ecb075950e29d4143565c1d24a96e1`. Native and build hunks are byte-identical to the prior patch; the previously installed extension SHA-256 is `44a0d14a43c8978154f28650895d7f35f4728df282f9eee8803ca42542e6a353`.

For bounded behavior diagnosis, the previous installed Python loaded the newly selected `shlex.py` in an overlay through [`shlex_binding_diagnostic.py`](shlex_binding_diagnostic.py). Each of 18 cases ran in a separate process and compared public `split` with the original Python split body in the same module. All processes exited successfully and matched tokens, errors, and spy-call counts. The ordinary case still cached the native scanner; changed bindings and hooks used the Python path. No test suite, formatter, linter, hook, full build, or timing comparison ran. An initial diagnostic that mutated hooks sequentially was discarded because a changed `__new__` polluted later cases; isolated processes replaced it. An initial source regeneration sought an absent old UUID stage; extraction from the verified pinned cache replaced that attempt.

The build recipe for a future comparison is `python3 rust-cpython/build.py build --variant shlex-binding-guard --strptime-numeric --uuid-canonical --shlex-split`. Unrelated Docker work was consuming CPU during this revision, so prior speed and resource inferences cannot be carried forward without fresh quiet-host pairs. Arbitrary import finders and mutations of the new private guard variables were outside this bounded audit.
