# Next independent stdlib target after zlib: URL percent quoting

## Decision

**Proceed with a bounded `urllib.parse` public-workload measurement; defer a Rust kernel until that measurement establishes useful headroom.** The first operation to investigate is `urllib.parse.quote` on ordinary text components, with `quote_from_bytes` as the smallest candidate implementation boundary. This is independent of zlib and of the rejected `difflib` row-dictionary reuse mechanism. The tomllib parser remains deferred for the workload and compatibility reasons in `tomllib-target.md`. No code, dependency, or benchmark claim is proposed here.

The ranked map in `rust-cpython/README.md` places `ipaddress`, `urllib.parse`, and `json` at ranks 4–6. The current checked-in application evidence changes the immediate order:

| Area | Existing complete-workload call path | Source boundary and decision |
| --- | --- | --- |
| `ipaddress` | No direct `ipaddress` call appears in `benchmarks/workloads/` or its checked-in catalog application. Django or other dependencies may call it internally, but this has not been measured. | `Lib/ipaddress.py` is Python code, but a routing-table workload would first need a real application use case. **Defer** until a profile shows one. |
| `urllib.parse` | The checked-in catalog application has `normalize_url` calling `urlsplit`, `unquote`, `quote`, and `urlunsplit`, and `stable_key` calling `quote` per component (`benchmarks/workloads/fixtures/tooling/python_corpus/catalog_service/normalize.py`). The registered `pylint_source` workload reads this source but does **not** execute those functions. | `quote` reaches Python `quote_from_bytes`, whose byte mapping is a plausible narrow native scan. **Measure** a complete catalog URL/key task before implementation. |
| `json` / `_json` | `benchmarks/workloads/django_app/views.py` returns `JsonResponse`; the WSGI/ASGI request workload decodes that body with `json.loads`. The catalog fixture encodes/decodes entries, HTTP responses, snapshots, and exports. The benchmark harness itself also emits JSON, which is not application work. `serialization_roundtrip` is pickle work despite its JSON result digest. | `Lib/json/encoder.py` already calls `_json.make_encoder`; `Lib/json/scanner.py` selects `_json.make_scanner`, backed by `Modules/_json.c`. The current C accelerator is a strong control, and full-document replacement has a larger hook/error contract. **Defer** until request or catalog profiling identifies remaining JSON CPU. |

The present workload suite therefore does not yet establish a URL bottleneck. It supplies a realistic call path and a small, separable hypothesis that can be measured without changing CPython's public API.

## Pinned source and narrow diagnostic

The source inspected was the no-Rust installation of the locked CPython 3.16 fork at `b812b4a7b9efaca46b98544a8633b7d7e454166b`: `Lib/urllib/parse.py`. `quote(str)` performs encoding and forwards to `quote_from_bytes`. That function validates bytes/bytearray, normalizes `safe` to ASCII bytes, returns an unchanged ASCII string for always-safe input, then maps bytes through cached `_Quoter.__getitem__`; inputs at or above 200,000 bytes use square-root-sized chunks to limit temporary memory. `unquote` and `urlsplit` are separate public operations with different parsing/error rules. The first kernel must not absorb them merely because the catalog task calls them too.

One short diagnostic used the pinned no-Rust interpreter and `cProfile` around 2,000 pairs of the catalog application's complete `normalize_url` and `stable_key` calls. The URL included percent-escaped credentials, an IPv6 host, path, query, and fragment; the key had three Unicode/reserved-character components. The observed final pair was `('https://User%20Name:p%40ss@2001:db8::1:8443/a/../cafe%CC%81?q=%2F&lang=en#frag', 'caf%C3%A9%20au%20lait/request%2Fresponse/unicode%20%CF%89')`. `cProfile` recorded 363,085 calls and 0.102 s **instrumented** elapsed time. The 10,000 `quote` calls accounted for 0.025 s cumulative; their 10,000 `quote_from_bytes` calls accounted for 0.019 s cumulative. `unquote` accounted for 0.019 s, `normalize_url` for 0.072 s, and `stable_key` for 0.029 s; cumulative figures overlap. The enclosing `/usr/bin/time -l` command reported 0.13 s user CPU, 0.02 s system CPU, 26,574,848 bytes maximum RSS, zero swaps, and 0.22 s wall for startup, imports, fixture work, and profiling together.

This locates calls, not savings. It uses one synthetic URL/key pair repeatedly, leaves `urlsplit`'s cache warm, and does not represent the frequency or input distribution of a deployed application. Profiling changes the cost mix; none of these times is a speed baseline or candidate comparison. The diagnostic consumed far below the 30 CPU-second and 512 MB RSS lane limits. No build or long benchmark was run under current host load.

## Proposed behavioral boundary

Keep public `quote`, `quote_plus`, `urlencode`, their argument and encoding checks, and `quote_from_bytes`'s public validation and `safe` normalization in Python. A first optional native helper could accept **exact `bytes` input and exact normalized `bytes` `safe`**, return the same ASCII `str`, and run once per complete byte string. It must use CPython's unreserved set, uppercase `%HH`, and the same handling of slash and custom `safe`; preserve `quote_from_bytes`'s empty and always-safe fast exits. Leave `bytearray`, subclasses, unusual `safe` iterables, and custom `encoding`/`errors` paths on Python initially. A guard must demonstrably fire for catalog `quote(str, safe="")` after UTF-8 encoding. Do not replace `urlsplit` or `unquote` in the first patch.

Exact output and API behavior matter: non-ASCII `safe` is ignored; `quote` accepts str or bytes with different encoding rules; `quote_plus` turns spaces into `+`; `urlencode` allows a caller-supplied `quote_via`; `clear_cache` and the cached quoter affect Python state even if the proposed path bypasses the cache. Large inputs currently use chunking specifically to avoid temporary-memory growth. The no-Rust implementation remains the oracle and fallback. Do not add a URL crate: its parsing rules would not establish CPython quoting compatibility, and dependencies require a separate scope decision.

The unchanged primary suite is `Lib/test/test_urlparse.py`, especially quoting, `quote_from_bytes`, `unquote_to_bytes`, `urlencode_quote_via`, and cache cases; include `Lib/test/test_urllib.py` for public consumers. Differential cases should cover all 256 byte values, empty and always-safe inputs, Unicode encodings and failures, `safe` as str/bytes/bytearray, malformed percent escapes in neighboring `unquote`, str/bytes subclasses, errors and exact messages, and inputs around the 200,000-byte chunk threshold. Run the suite against immediate no-Rust control and candidate before interpreting performance.

## Exact next reversible step and gate

Add one registered complete workload, for example `catalog_url_normalize`, in `benchmarks/workloads/` using the checked-in catalog functions. One logical operation should normalize a deterministic batch of mixed real-looking URLs and produce stable keys, then hash the entire output; record input strings, counts, length distribution, and output digest. Include plain/Unicode/reserved paths, credentials, query/fragment, IPv4/IPv6 hosts, already escaped and malformed escapes, repeated and unique URLs, and short/large components. Keep warm steady-state and fresh-process import cases separate. The workload should call the public catalog functions so `urlsplit`, `unquote`, `quote`, `urlunsplit`, Unicode normalization, and path processing remain in the measured task. A separate diagnostic profile may apportion time among those operations; it must not stand in for complete-workload timing.

First run that workload unchanged on the no-Rust fork and the matched upstream control, with serial self-comparison and CPU/RSS observations when the host is quiet. If `quote_from_bytes` is a meaningful share of the complete task and the exact-bytes guard would cover common calls, try the single guarded helper in an isolated patch. Retain it only if unchanged tests and differential behavior pass and serial paired complete tasks show useful wall and kernel user/system CPU gains beyond self-comparison noise, with no material cold-start, peak/retained memory, allocation, or installed-size regression. Record raw observations and fallback rate. If quotation is a small share, or native crossing/memory costs erase gains, stop this target and revisit the ranked map. Current macOS unique/proportional memory and allocation coverage is incomplete, so a timing win alone would remain provisional.
