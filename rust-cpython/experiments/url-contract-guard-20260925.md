# URL route contract check, 2026-09-25

The accepted optional quote branch skipped `_byte_quoter_factory` for exact `bytes`. On the pinned CPython 3.16 source, replacing that factory with `lambda safe: lambda byte: 'X'` makes `quote_from_bytes(b' ', safe=b'/')` return `'X'`. The installed pre-guard parser (`sha256 85ac4db38a30e3b12dd78ff0a5b83baa61caedebc3a44c33cd45c85c3279acee`) returned `'%20'`; the revised parser returns `'X'`. The installed native extension used for this diagnostic has SHA-256 `a9f2cf9d0c6bb735840af8c10632a175ebf935437ca02afb713291a7596af7f1`. The revised route first obtains the original quoter and computes `bs_len` once, then admits native quotation only while original Python helper bindings, quoter methods, safe set, and the quoter cache are canonical at entry. It uses `dict.__len__` directly so a replaced `_Quoter.__len__` is not called by the guard. A module-level `type` replacement no longer raises from the new guard. A plain `b' '` input still entered native quotation in the bounded overlay probe; factory replacement, a changed cached byte, a changed safe set, a replaced `__missing__` or `__getattribute__`, and a replaced `map` took the Python path and matched pinned-source results.

The quote route still changes observable private cache state after a native hit. In a fresh module, `quote_from_bytes(b' ', safe=b'/')` returned `'%20'` on both sides, but the pinned Python path left `{32: '%20'}` in `_byte_quoter_factory(b'/').__self__`, while the revised native path left that dict empty (`dict.__len__` 1 versus 0; `.get(32)` `'%20'` versus `None`). A caller can inspect or use this quoter directly after the call. The guard detects later cache edits before another native hit, but it does not reproduce Python's cache population. Reproducing each Python map lookup would remove the basis for assuming a native speed benefit; no such route or speed comparison was evaluated. Treat optional quote as experimental and unqualified for strict Python state equivalence until this difference is preserved or explicitly accepted as a contract change.

A second bounded probe found four concrete guard defects before this amendment: replacing `_Quoter.__len__` made the first revision raise where pinned Python returned `'%20'`; stateful `_Quoter.__getattribute__` made pinned Python return `' '` where the first revision returned `'%20'`; replacing module `map` made pinned Python return `'X'` where the first revision returned `'%20'`; replacing module `len` while changing `__missing__` made the first revision call `len` twice where pinned Python called it once. The amended overlay matched pinned Python for all four cases: `'%20'`, `' '`, `'X'`, and `'X'` with one `len` call, respectively. It also matched the earlier factory, cached-byte, safe-set, `__missing__`, and `type` cases. The plain case recorded one native hit; hook-changed cases requiring fallback recorded zero. These were isolated source overlay diagnostics using the byte-identical pre-existing quote extension, not a compiled revised installation.

Public `unquote_to_bytes` has no Rust branch; the optional `0004` patch routes public `unquote`. With `_hextobyte = {b'41': b'Z'}`, pinned `unquote('%41')` returns `'Z'`, while `0004` source dispatch returns `'A'`; both `unquote_to_bytes('%41')` calls return `b'Z'`. With `_hextobyte = None`, pinned `unquote('%41')` initializes the mapping; the `0004` dispatch leaves it `None`. The `0004` diagnostic used a Python stub for its native entry point because the available installed extension contains only the quote kernel. These source-level results are sufficient to stop the optional unquote route as behavior-preserving: in-place mapping edits can alter its public output and cannot be excluded by a cheap Python identity guard. `0004` was not edited here.

No build, tests, formatter, linter, hook, benchmark, or resource measurement was run. Earlier quote or unquote performance ratios are pre-guard diagnostics; the revised quote guard needs a fresh quiet-host comparison before a speed verdict. The overlay covered representative hook mutations and route hits, not the full public differential suite or a newly built installation.
