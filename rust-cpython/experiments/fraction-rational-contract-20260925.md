# `Fraction` native-route contract audit

**Verdict: keep the optional scanner with the narrower guard.** The earlier patch could change public `Fraction("12/35")` behavior when a caller changed Python's import hook or the private module entry. A blocking `__import__` hook made the candidate raise `RuntimeError` where the control returned `12/35`; a fake private module returned `7`; a `None` private-module entry raised `ModuleNotFoundError`. Replacing the module's `type` binding also caused one extra observable call in the candidate. These differences occurred before or during the native shortcut and did not depend on malformed input.

The revised `0010-rust-fraction-rational.patch` requires the original `type`, `int`, regex, `__import__`, `sys`, and `sys.modules` bindings before scanning. It checks for an existing private-module entry before import. On first use, it accepts only an exact module with a built-in `scan` function bound to that module under the expected name, then caches the verified function. Later calls require the same `sys.modules` entry and use that function; changing `module.scan` cannot redirect output. A replaced or invalid module entry returns to the original regex and integer conversion. The ordinary exact-string path still loads the genuine extension. The unchanged normalization, error, subclass, and noncanonical paths remain in Python. A delegating replacement for `isinstance` made three calls in control, prior candidate, and revised source, so the audit found no extra call to guard there.

Fresh verified source application and reverse checks passed for default, fraction-only, candidate stack, and all-optional selections, changing 8, 11, 20, and 26 intended paths. The revised `fractions.py` SHA-256 is `8275fd7933de5062f6d8f82169caa306980ed398fe1376fe1be1906ae458ee6c`. Bounded fresh-process diagnostics loaded that source through `PYTHONPATH` using the previously built candidate interpreter and its unchanged native extension. Every demonstrated divergence above returned to control behavior; an exact `ModuleType` with a fake Python scanner fell back, and changing the module entry or `scan` attribute after first use still returned `12/35`. Exact commands and outcomes are in [compact evidence](data/fraction-rational-contract-20260925.json).

No full build or test suite ran for this Python guard-only revision. The previous whole-ledger timing and memory observations describe **pre-guard source under external CPU load**. Quiet-host performance, memory, broader semantics, and Linux qualification remain open. Custom import machinery can still observe the first private-module import on an eligible call; this audit establishes the listed guard boundaries and output behavior, not complete observational equivalence with regex parsing.
