**Verdict: retain the revised guard as an opt-in source candidate, pending an installed native diagnostic and a quiet-host comparison.** The patch still computes the same two checksums in Rust only for exact 512-byte `bytes`. The revised Python entry checks the bindings used to select that route and keeps the original two `struct.unpack_from`/`sum` expressions available as the fallback.

The original `calc_chksums` body is exactly two unpack/sum expressions using formats `148B8x356B` and `148b8x356b`, each with an added 256. The Rust byte scan retains that arithmetic and the original 512-byte bound.

The guard now rejects changed `type`, `bytes`, `len`, `struct`, `struct.unpack_from`, `sum`, `builtins.__import__`, `sys.modules`, and `sys.meta_path` bindings. It records the import finder identities, so later list edits also cause fallback. An already loaded `_rust_tar_checksum` is ignored on first eligible call. Once a native scanner is accepted, the code retains its bound function and uses it only while the same module remains registered in `sys.modules`; changing `module.scan` cannot redirect the cached call. A cold `import tarfile` still leaves the private extension unloaded by construction.
