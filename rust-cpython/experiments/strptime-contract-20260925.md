# Numeric `strptime` binding and import contract

The warmed fixed-width `datetime.strptime` route skipped callbacks that pinned `_strptime` normally reaches. Before cache lookup, `_strptime` calls the module's replaceable `enumerate` and `isinstance` to check arguments. After regex matching, it calls replaceable `len` on the input. The old guard also called replaceable `type` before checking its identity. Its per-call `from _rust_strptime_numeric import scan` could invoke a replaced `__import__` or accept a fake module in `sys.modules`, neither of which the baseline parser does.

A source-only public-API diagnostic used the same pinned 3.16 interpreter and exact warm numeric input on baseline and old guarded `_strptime.py`. Replacing `isinstance` or `enumerate` made baseline raise `RuntimeError` while the guard returned a datetime. Replacing `type` made only the guard raise. Replacing `len` made baseline raise `ValueError` while the guard returned. A replaced `__import__` made only the guard raise. A fake `_rust_strptime_numeric` in `sys.modules` made the guard return `2000-01-01 00:00:00` while baseline returned `2024-03-17 11:22:33`. These are concrete output and exception differences, not timing effects.

The revised `0007-rust-strptime-numeric.patch` checks the original `type`, `isinstance`, `enumerate`, `len`, `__import__`, and `sys.modules` bindings before calling `type(...)` or entering the scanner route. The first scanner import is allowed only when its module key is absent; the result must be a built-in function bound to the exact module type, with matching `_rust_strptime_numeric` module and function names. Later calls use the captured scanner while the same module remains installed, without reading its mutable `scan` attribute. A preloaded module, replaced import binding, or changed module identity falls through to the parser. This conservatively forgoes acceleration when another caller loaded the real private module first.

The same six source-only mutation cases now match baseline values or exception type and message using [`strptime_binding_diagnostic.py`](strptime_binding_diagnostic.py). A follow-up probe changed the captured scanner module's `__class__` to a module subclass that raises on `scan` attribute access: the previous guard raised `RuntimeError`, while baseline and the final guard returned the same datetime. An ordinary second parse bound the native scanner and observed the expected module/function names. Fresh verified extraction and patch application passed for default, numeric-only, and all-optional selections, changing exactly 8, 11, and 26 patch-declared paths. The final numeric and all-optional `Lib/_strptime.py` SHA-256 is `b939f0602fe8df9b325891f92465cdd8c8913b57fe92473b182e720eacf6f2a7`. The scanner extension used for the overlay is byte-identical to the prior built extension; only `_strptime.py` changed.

One bounded 60,000-record final overlay pass per arm produced the same complete digest, `bb2b012282c2f8f0bad78f553fe946f3f093c96bfb8eca6a5077b5ee2e1a9473`. The baseline process used 0.35 s wall, 0.31 s user plus 0.01 s system CPU, 36,749,312 bytes peak RSS, and zero swaps; the final source used 0.27 s wall, 0.23 s user plus 0.01 s system CPU, 36,995,072 bytes peak RSS, and zero swaps. Both used `-S -B`, `PYTHONDONTWRITEBYTECODE=1`, an empty worktree-local bytecode prefix, and the same interpreter and extension bytes. Docker was consuming CPU, so this pair is an output and resource diagnostic, not a speed comparison. The earlier 0.758 wall and 0.774 CPU ratios belong to the **pre-revision guard** and do not qualify this revision.

The compact [evidence](data/strptime-contract-20260925.json) records all 21 mutation attempts, both ordinary route checks, both fresh source selections, and both bounded workload pairs. Import finder changes and broader Python mutation behavior remain unqualified. A fresh quiet-host speed and memory comparison is needed before a performance verdict; no full PGO rebuild was run for this source-only revision.

**Recommendation:** retain the corrected optional guard for further qualification. The proven callback and private-module gaps are closed in the bounded diagnostic, with the ordinary native route still reachable.
